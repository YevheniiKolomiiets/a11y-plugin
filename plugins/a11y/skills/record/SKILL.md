# /a11y:record

Записує рішення. **Код застосунку не змінюється.** Пишуться лише документ рішень і `lab.json` (з перезбіркою `lab.html`).

Файли плагіна:
- шаблон документа: `${CLAUDE_PLUGIN_ROOT}/templates/decisions.md`
- таблиці контрасту: `node ${CLAUDE_PLUGIN_ROOT}/scripts/contrast-table.mjs <lab.json> --decision <id> [--themes …] [--lang en]`
- збірка лабораторії: `node ${CLAUDE_PLUGIN_ROOT}/scripts/build-lab.mjs <lab.json>`
- формат даних: `${CLAUDE_PLUGIN_ROOT}/references/lab-schema.md`

Аргументи користувача: `$ARGUMENTS`

## 1. Що записуємо

Визнач рішення з аргументів або з останнього повідомлення:

- **Рядок з лабораторії** `[a11y:lab] decision=<id> theme=<тема> option=<X>[ (edited)]` і кольори цієї теми — джерело правди: беруться саме ці hex, навіть якщо вони відрізняються від варіанта в `lab.json` (користувач підправив). Записується **лише тема з рядка**; інші теми рішення лишаються відкритими, навіть якщо у варіанта для них є значення. Рядок без `theme=` (стара лабораторія) з кольорами кількох тем — спитай, які теми користувач справді обирав.
- **Кілька рядків одразу** (кнопка «Copy all choices» у лабораторії) — кожен блок `[a11y:lab]` — окремий запис за цими самими правилами; `lab.json` перезбирається один раз наприкінці, документ — по розділу на рішення.
- **Словами** («запиши severity, варіант A») — значення з `options` у `lab.json`; якщо тему не названо — спитай, для якої.
- **Рішення без нових кольорів** — «лишаємо як є», правило без нових значень (який токен бере елемент), «поза обсягом», структурне виправлення. Теж записуються, окремим розділом.

Записуй лише те, що користувач обрав. Якщо незрозуміло, яке рішення чи варіант мається на увазі, — спитай одним питанням, не вгадуй.

## 2. Документ рішень (перший запис)

Якщо в `lab.json` немає `meta.decisions`:

1. **Де.** Запропонуй шлях: тека spec / тікета, якщо вона є в проєкті (наприклад, `specs/<номер>/palette.md`), інакше `decisions.md` поруч з лабораторією. Користувач підтверджує або дає свій.
2. **Мова.** Спитай мову документа. Запам'ятай у `meta.decisionsLang`.
3. Створи документ з `templates/decisions.md` (шапка, «Поза цим документом», «Відкриті питання») і запиши шлях у `meta.decisions`.

Далі ці два питання не ставляться.

## 3. Запис

Одразу, без чернетки на погодження:

1. **`lab.json`.**
   - Рішення з варіантом: `chosen.<тема> = <X>` (інші теми в `chosen` не чіпай). `status: "recorded"` — лише коли в `chosen` є всі теми рішення (`themes`, якщо задано, інакше всі теми лабораторії), інакше `open`. Якщо прийшли `(edited)`-значення — це вже не варіант агента, а кольори користувача: додай варіант `{ "id": "manual", "manual": true, "from": "<X>", "label": "Edited manually", "tokens": { "<тема>": … } }` з цими значеннями (або допиши тему в наявний `manual`) і зроби його `chosen.<тема>`. У лабораторії він показується як «Edited manually», без літери варіанта; у документі — як «підібрано вручну на основі варіанта X», без літери варіанта як назви. Прибери ці токени з `proposal`, якщо вони там дублюються.
   - Рішення без варіанта, але зі зміною значень (структурне, правило з новими значеннями токенів у рядках) — значення в `proposal`.
   - Перезбери: `build-lab.mjs`. Збірка має пройти.
2. **Таблиці.** `contrast-table.mjs --decision <id>` (або `--rows <ids>` для рішення без варіантів) з `--lang`, якщо документ не українською. Для `--decision` скрипт сам бере лише записані теми рішення. Таблиці вставляються як є — жодного контрасту з голови.
3. **Розділ документа** між маркерами з шаблону (HTML-коментарі `a11y:decision <id>` і `/a11y:decision <id>`):
   - правило / обмеження і чому обрано саме це (одне речення про відкинутий варіант, якщо був);
   - таблиця токенів і таблиця контрасту зі скрипта;
   - найменший запас, якщо він малий;
   - «Що міняється в коді»: з `where` рядків і `source` токенів — `файл:рядок`, що зараз → що буде, окремим пунктом для кожної теми, якщо `source` по темах; нові токени — де оголосити;
   - мінуси, погоджені свідомо; «Відкрите питання: …» для невирішеного, зокрема «<тема>: ще не обрано» для кожної теми, якої немає в `chosen`;
   - «Що міняється в коді» — лише для записаних тем.
   Якщо розділ з таким id уже є — заміни його між маркерами (повторний запис = оновлення, не дублікат).
4. **«Відкриті питання»** наприкінці документа — перезбери зі всіх розділів.

## 4. Звіт користувачу

Коротко: що записано (рішення, варіант, ключові значення), де (посилання на розділ документа), що змінилось у лабораторії (рішення стало «записано»; збережені в браузері правки скинулись, бо змінились дані). Нічого не пропонуй наступним кроком, крім наступної групи, якщо користувач про неї вже казав.

## Правила

- Записане рішення не змінюється без явного «перепиши»; тоді — той самий запис наново, розділ замінюється.
- Документ і `lab.json` завжди узгоджені: після кожного запису значення в розділі = значення в `lab.json`.
- Не дописуй у документ того, чого не обговорювали. Якщо помітив проблему по дорозі — скажи окремо, а не вписуй мовчки.
